# P0 ก่อนเริ่ม · P1 ขั้นวิเคราะห์

---

### P0-1 · ตรวจความพร้อมของเครื่อง

**ใช้ตอน:** ก่อนเริ่มทุกอย่าง เปิด `agy` ครั้งแรกในโฟลเดอร์ว่าง

```text
ตรวจความพร้อมของเครื่องฉันสำหรับโปรเจกต์ Next.js แล้วรายงานเป็นตาราง
- node เวอร์ชันอะไร (ต้อง 20 ขึ้นไป)
- npm เวอร์ชันอะไร
- git ติดตั้งหรือยัง และตั้งค่า user.name กับ user.email แล้วหรือยัง
- ตอนนี้อยู่ในโฟลเดอร์ไหน

ห้ามติดตั้งอะไรเอง ถ้ามีอะไรขาด ให้บอกฉันว่าต้องติดตั้งอะไรและใช้คำสั่งไหน
ฉันจะติดตั้งเอง
```

**ควรได้:** ตาราง 4 แถว พร้อมเวอร์ชันจริง
**สัญญาณว่าผิดทาง:** มันเริ่มรัน `npm install` หรือ `winget install` เอง → กด `Esc` ทันที

### P0-2 · สร้างโครงโปรเจกต์

**ใช้ตอน:** งานที่ 1 ของขั้นเขียนโปรแกรม (หรือจะทำตั้งแต่ช่วงเช้าก็ได้)

```text
สร้างโปรเจกต์ Next.js ใหม่ชื่อ rsu-event-register ในโฟลเดอร์ปัจจุบัน
ใช้ TypeScript, App Router, Tailwind CSS, วางโค้ดไว้ใต้ src/ และตั้ง alias import เป็น @/*
ห้ามติดตั้ง library อื่นเพิ่มนอกจากที่ create-next-app ให้มาเอง

เสร็จแล้วให้แสดงโครงไฟล์ที่ได้ และบอกฉันว่าต้องรันคำสั่งอะไรเพื่อเปิดดูในเบราว์เซอร์
```

**ควรได้:** โฟลเดอร์ `src/app/` พร้อม `page.tsx` และคำสั่ง `npm run dev`
**สัญญาณว่าผิดทาง:** ได้โฟลเดอร์ `pages/` แทน `src/app/` → นั่นคือ Pages Router ให้สั่งทำใหม่

### P0-3 · เปิด context ใหม่ ★ ใช้บ่อยที่สุดของวัน

**ใช้ตอน:** ทุกครั้งที่เปิดแชท/หน้าต่าง agent ใหม่ — ก่อนสั่งงานอื่นเสมอ

```text
ก่อนทำงานใด ๆ ให้อ่าน 4 ไฟล์นี้ก่อน แล้วสรุปให้ฉันฟังสั้น ๆ ว่าเข้าใจอะไรบ้าง
1. AGENTS.md
2. requirements.md
3. design.md
4. db/schema.sql

สรุปให้ไม่เกิน 10 บรรทัด และบอกมาด้วยว่ากติกา R1 ถึง R5 คืออะไรบ้าง
ห้ามแก้ไฟล์ใด ๆ ในรอบนี้ รอฉันสั่งงานถัดไป
```

**ควรได้:** สรุปที่มีชื่อ stack ถูกต้อง และเล่า R1–R5 ได้ครบ 5 ข้อ
**สัญญาณว่าผิดทาง:** มันเล่า R1–R5 ผิดหรือขาดข้อ → แปลว่ามันอ่านไม่ครบ ให้สั่งอ่านใหม่ทีละไฟล์

### P1-1 · ให้ AI สัมภาษณ์เรากลับ ★ เทคนิคที่เปลี่ยนผลลัพธ์มากที่สุด

**ใช้ตอน:** prompt แรกสุดของขั้นวิเคราะห์

```text
ฉันอยากทำระบบลงทะเบียนกิจกรรมสำหรับงาน [ชื่องานของฉัน]

อย่าเพิ่งเขียนโค้ด และอย่าเพิ่งสรุปสเปกให้ฉัน
ให้ถามฉัน 5 คำถามที่จำเป็นที่สุดก่อน ทีละคำถาม รอฉันตอบข้อหนึ่งแล้วค่อยถามข้อถัดไป

คำถามต้องเป็นเรื่องที่ "ถ้าไม่รู้แล้วจะออกแบบระบบผิด"
ไม่ใช่เรื่องสีหรือความสวยงาม
```

**ทำไมได้ผล:** คนตอบคำถามเก่งกว่าเขียนสเปก คำถามของ AI จะดึงสิ่งที่เรารู้อยู่แล้วแต่ลืมบอกออกมา
**ควรได้:** คำถามทีละข้อจริง ๆ เช่น รับกี่คน · มีค่าลงทะเบียนไหม · ใครดูรายชื่อได้บ้าง
**สัญญาณว่าผิดทาง:** มันยิงคำถามมา 5 ข้อรวดเดียว หรือสรุปสเปกให้เลย → สั่งใหม่ว่า "ทีละคำถาม"

---

### P1-2 · สรุปบทสนทนาเป็นไฟล์

**ใช้ตอน:** ตอบคำถามจาก P1-1 ครบแล้ว

```text
สรุปทุกอย่างที่เราคุยกันมาเป็นไฟล์ requirements.md ที่รากโปรเจกต์
ใช้หัวข้อเหล่านี้เท่านั้น ห้ามเพิ่มหัวข้ออื่น

## ผู้ใช้และเป้าหมาย
## หน้าจอ 3 หน้า
## โครงสร้างข้อมูล 2 ตาราง
## กติกา R1-R5
## ฟิลด์เพิ่มเติมของฉัน
## Out of scope

เขียนเฉพาะสิ่งที่ฉันบอกไปจริง ๆ ห้ามเติมฟีเจอร์ที่ฉันไม่ได้พูดถึง
หัวข้อไหนข้อมูลยังไม่พอ ให้เขียนว่า "ยังไม่ได้ตัดสินใจ" แล้วถามฉัน อย่าเดาแทนฉัน
```

**ทำไมต้องเป็นไฟล์:** ปิดหน้าต่างแล้วบทสนทนาหายหมด แต่ไฟล์ยังอยู่ในโฟลเดอร์
**ควรได้:** ไฟล์ `requirements.md` โผล่ในโฟลเดอร์จริง (เปิดดูด้วยตาเอง อย่าเชื่อคำพูด)
**สัญญาณว่าผิดทาง:** มันพิมพ์เนื้อหาในแชทแต่ไม่ได้สร้างไฟล์ → สั่งว่า "สร้างเป็นไฟล์จริงในโฟลเดอร์"

### P1-3 · แปลงเป็น user story + acceptance criteria

**ใช้ตอน:** มี `requirements.md` แล้ว

```text
จากไฟล์ requirements.md ให้ทำ 2 อย่าง แล้วเขียนต่อท้ายในไฟล์เดิม (ห้ามสร้างไฟล์ใหม่)

1. เขียน user story อย่างน้อย 3 ข้อ รูปแบบ
   ในฐานะ [ใคร] ฉันต้องการ [ทำอะไร] เพื่อ [ได้อะไร]

2. แปลงกติกา R1 ถึง R5 เป็น acceptance criteria ข้อละอย่างน้อย 3 ข้อย่อย
   แต่ละข้อย่อยต้อง "ทดสอบได้" คือบอกได้ว่า ทำอะไร แล้วต้องเกิดอะไรขึ้น
   เช่น "กรอกเบอร์ 9 หลักแล้วกดส่ง ต้องขึ้นข้อความเตือน และต้องไม่มีแถวใหม่ในฐานข้อมูล"

ข้อไหนที่คุณเขียนแล้วยังทดสอบไม่ได้ ให้บอกฉันว่าเพราะอะไร
```

**ควรได้:** acceptance criteria รวมอย่างน้อย 15 ข้อย่อย ครบ R1–R5
**สัญญาณว่าผิดทาง:** ได้ข้อความกว้าง ๆ อย่าง "ระบบต้องใช้งานง่าย" → นั่นทดสอบไม่ได้ สั่งให้เขียนใหม่

### P1-4 · ให้ AI หาช่องโหว่ในสเปกของเราเอง ★

**ใช้ตอน:** ก่อนจบขั้นวิเคราะห์ — ขั้นตอนที่คนข้ามแล้วเสียเวลาตอนบ่าย

```text
อ่านไฟล์ requirements.md แล้วทำตัวเป็นคนที่ต้องเขียนโค้ดตามสเปกนี้จริง ๆ

บอกฉันมา 5 จุดที่สเปกยังกำกวมจนคุณต้องเดาเอง
เรียงจากจุดที่ "เดาผิดแล้วเสียหายมากที่สุด" ลงมา
แต่ละจุดให้บอกว่า ถ้าเดาไปคนละทางกับที่ฉันคิด ผลลัพธ์จะต่างกันยังไง

ห้ามเขียนโค้ด ห้ามแก้ไฟล์ ห้ามเสนอทางแก้ — ชี้จุดกำกวมอย่างเดียว
```

**ควรได้:** คำถามแบบ "ที่นั่งเต็มแล้วให้เข้าคิวสำรองไหม" หรือ "ยกเลิกการลงทะเบียนได้ไหม"
**ทำต่อยังไง:** ตอบทีละข้อ แล้วสั่ง P1-2 ซ้ำเพื่ออัปเดตไฟล์
**สัญญาณว่าผิดทาง:** มันตอบว่า "สเปกชัดเจนดีแล้ว" → สเปกไม่เคยชัดเจน สั่งใหม่ว่า "หาให้ได้ 5 จุด"

### P1-5 · ตัดขอบเขตให้พอดีเวลา

**ใช้ตอน:** ปิดขั้นวิเคราะห์

```text
จากไฟล์ requirements.md ถ้าฉันมีเวลาเขียนโปรแกรมแค่ 90 นาที

บอกมาว่าอะไรคือ 6 งานที่ต้องทำให้ได้ และอะไรที่ควรตัดไปทำทีหลัง
เรียงงานตามลำดับที่ทำแล้วเห็นผลเร็วที่สุด
และแต่ละงานต้อง "จบในตัวเอง" คือทดสอบได้ทันทีโดยไม่ต้องรองานถัดไป

เขียนคำตอบต่อท้ายไฟล์ requirements.md ใต้หัวข้อ ## แผนงาน 6 ขั้น
```

**ควรได้:** งานที่แต่ละงานใช้เวลา 10–15 นาที และทดสอบได้เป็นเอกราช
**สัญญาณว่าผิดทาง:** ได้งานอย่าง "ทำ backend" หรือ "ทำ frontend" → ใหญ่เกินไป สั่งให้ซอยอีก
