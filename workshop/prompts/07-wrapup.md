### P7-1 · ตรวจความปลอดภัยรอบสุดท้าย ★

**ใช้ตอน:** ก่อนแจก URL ให้เพื่อนลงทะเบียน — ระบบนี้เก็บข้อมูลจริงของคนในห้อง

```text
ตรวจความปลอดภัยของโปรเจกต์นี้ให้ฉันรอบสุดท้าย ตอบเป็นตาราง 5 แถว

1. ใครอ่านตาราง registrations ได้บ้างตอนนี้
2. คีย์ลับมีโอกาสหลุดไปฝั่งเบราว์เซอร์ตรงไหนได้บ้าง
3. หน้าแอดมินป้องกันที่ชั้นไหนบ้าง และถ้าข้ามชั้นแรกไปได้จะเจออะไรต่อ
4. มีที่ไหนที่ log หรือแสดงข้อมูลส่วนบุคคลโดยไม่จำเป็น
5. ถ้าคุณเป็นคนที่อยากขโมยรายชื่อในระบบนี้ คุณจะลองทางไหนก่อน

รายงานอย่างเดียว ห้ามแก้อะไร ถ้าเจอช่องโหว่ให้เรียงตามความรุนแรง
```

**ข้อ 5 คือข้อที่ได้ผลที่สุด** — การให้มันคิดจากมุมคนโจมตี มักเจอสิ่งที่ checklist ปกติไม่เจอ

### P7-2 · ตรวจ PDPA

**ใช้ตอน:** ก่อนปิดวัน — ระบบนี้เก็บ ชื่อ · อีเมล · เบอร์โทร · คณะ = ข้อมูลส่วนบุคคลเต็มรูปแบบ

```text
ตรวจว่าระบบของฉันทำครบ 4 ข้อนี้หรือยัง ตอบเป็นตาราง ทำแล้ว/ยังไม่ทำ พร้อมบอกว่าอยู่ไฟล์ไหน

1. แจ้งวัตถุประสงค์ — บอกชัดว่าเก็บไปทำอะไร เก็บนานแค่ไหน ใครเห็นได้บ้าง
2. มีช่องให้ยินยอม — checkbox ที่ผู้ใช้ต้องติ๊กเอง ห้ามติ๊กไว้ล่วงหน้า
3. ลบข้อมูลได้ — มีช่องทางให้เจ้าของข้อมูลขอลบ และเราลบได้จริง
4. เก็บเท่าที่จำเป็น — ไม่มีฟิลด์ไหนที่ขอมาแต่ไม่ได้ใช้

ข้อไหนที่ยังขาด ให้บอกว่าต้องเพิ่มอะไร แต่ยังไม่ต้องแก้
```

**เรื่องที่ต้องตกลงกันก่อนจบวัน:** ข้อมูลเพื่อนในห้องที่อยู่ในระบบของแต่ละคน
**จะถูกลบเมื่อไหร่ ใครลบ ลบยังไง** — เขียนไว้ใน README ของตัวเองด้วย

### P7-3 · เขียน README ของ repo ตัวเอง

**ใช้ตอน:** การบ้าน — repo ที่ไม่มี README คือ repo ที่เอาไปใส่ portfolio ไม่ได้

```text
เขียนไฟล์ README.md สำหรับ repo นี้ ให้คนที่ไม่เคยเห็นโปรเจกต์นี้มาก่อนอ่านรู้เรื่อง

ต้องมี
- ระบบนี้ทำอะไรได้ (ตาราง 3 หน้า)
- ใช้ stack อะไรบ้าง
- วิธีรันในเครื่องตัวเอง ตั้งแต่ clone จนเปิดเบราว์เซอร์ได้ (คำสั่งจริงที่คัดลอกไปรันได้)
- ต้องตั้งตัวแปร environment อะไรบ้าง (ชื่อเท่านั้น ห้ามใส่ค่าจริง)
- ลำดับการรันไฟล์ SQL
- กติกา R1-R5 ที่ระบบนี้ต้องทำได้
- ข้อมูลส่วนบุคคลถูกเก็บนานแค่ไหน และขอลบได้ที่ไหน

เขียนเป็นภาษาไทย ยกเว้นชื่อคำสั่งและชื่อไฟล์
ห้ามใส่ URL จริงของฐานข้อมูลหรือคีย์ใด ๆ
```

### P7-4 · ทำ 6 ขั้นนี้ซ้ำกับโปรเจกต์ของตัวเอง ★ ของที่เอากลับบ้านจริง ๆ

**ใช้ตอน:** หลังจบอบรม — นี่คือ prompt ที่ทำให้วันนี้ไม่จบแค่วันนี้

```text
ฉันเพิ่งทำระบบลงทะเบียนกิจกรรมเสร็จ ด้วยกระบวนการ 6 ขั้น
วิเคราะห์ → ออกแบบ → เขียนโปรแกรม → ทดสอบ → แก้บั๊ก → deploy

ตอนนี้ฉันอยากทำ [ชื่อระบบใหม่ของฉัน] ด้วยกระบวนการเดียวกัน

เริ่มจากขั้นที่ 1 ก่อน อย่าเพิ่งเขียนโค้ด
ถามฉัน 5 คำถามที่จำเป็นที่สุด ทีละคำถาม
แล้วสรุปเป็นไฟล์ requirements.md ที่มี user story และกติกาที่ทดสอบได้
```

**ของที่เอากลับบ้านไม่ใช่ระบบลงทะเบียน แต่เป็นวิธีทำงาน 6 ขั้นนี้ ที่ใช้ซ้ำได้กับทุกโปรเจกต์**

## จริยธรรมและความรับผิดชอบ — 3 เรื่องที่ต้องพูดก่อนปิดวัน

**1. ใครเป็นเจ้าของโค้ด**
โค้ดที่ AI ช่วยเขียน โดยทั่วไปถือว่าเราเป็นผู้ใช้และผู้รับผิดชอบผลงาน
แต่ AI อาจหยิบรูปแบบโค้ดที่มีสัญญาอนุญาตติดมาด้วย — ก่อนเอาไปใช้เชิงพาณิชย์ ควรตรวจ license ของทุก library

**2. ใครรับผิดถ้าระบบพัง**
ผู้ให้บริการ AI ไม่รับผิดชอบผลลัพธ์ที่เกิดจากโค้ด
**คนที่กด deploy คือคนที่รับผิดชอบ** ไม่ใช่เครื่องมือ

**3. ข้อจำกัดของ AI ที่ต้องรู้**
ตอบผิดแบบมั่นใจ · ความรู้เฉพาะทางจำกัด · อคติจากข้อมูลที่ใช้ฝึก ·
เผลอเปิดเผยข้อมูลลับถ้าเราแปะเข้าไปเอง · ไม่มีความรับผิดชอบตามกฎหมาย
