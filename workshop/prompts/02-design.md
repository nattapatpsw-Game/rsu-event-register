### P2-1 · ล็อก stack ตั้งแต่ประโยคแรก ★

**ใช้ตอน:** prompt แรกของขั้นออกแบบ และพูดซ้ำทุกครั้งที่เปิด context ใหม่ก่อนจะมี `AGENTS.md`

```text
โปรเจกต์นี้ใช้ Next.js 16 (App Router) + TypeScript + Tailwind CSS v4
+ Supabase (PostgreSQL) เท่านั้น และ deploy บน Vercel

- ห้ามเปลี่ยน framework และห้ามย้ายไป Pages Router
- ห้ามเพิ่ม library ใหม่โดยไม่ถามฉันก่อน ทุกครั้ง ไม่มีข้อยกเว้น
- ข้อความบนหน้าจอทั้งหมดเป็นภาษาไทย ชื่อตัวแปรและคอมเมนต์เป็นภาษาอังกฤษ
- ถ้าคุณคิดว่ามีทางที่ดีกว่า ให้บอกฉัน แต่ห้ามเปลี่ยนเอง

ตอบรับว่าเข้าใจแล้ว ยังไม่ต้องเขียนโค้ด
```

**ปัญหาที่กำลังกัน:** เปิดแชทใหม่รอบหน้า AI จะเสนอ stack ใหม่ — เช้า Next.js บ่าย Vite เย็น Express
แล้วโค้ดสามกองจะต่อกันไม่ติด
**สัญญาณว่าผิดทาง:** มันตอบว่า "แนะนำให้ใช้ Vite จะเร็วกว่า" แล้วเริ่มทำ → กด `Esc` แล้วสั่งใหม่

### P2-2 · ขอ schema จากสเปก

```text
จากไฟล์ requirements.md ให้ออกแบบตารางฐานข้อมูล 2 ตาราง สำหรับ PostgreSQL บน Supabase
แล้วเขียนเป็นไฟล์ db/schema.sql

เงื่อนไขที่ห้ามพลาด
- เบอร์โทรเก็บเป็น text ไม่ใช่ number
- วันเวลาเก็บเป็น timestamptz
- ตาราง registrations ต้องมี event_id ที่อ้างกลับไปที่ events.id
- ฟิลด์เพิ่มของฉันคือ [ชื่อฟิลด์ของฉัน] ต้องอยู่ในตาราง registrations ด้วย
- กติกา R1 R3 R5 ต้องบังคับที่ระดับฐานข้อมูล ไม่ใช่แค่ในโค้ด

ก่อนเขียนไฟล์ ให้อธิบายให้ฉันฟังก่อนว่า constraint หรือ index แต่ละอันบังคับกติกาข้อไหน
แล้วรอฉันบอกว่า "เขียนได้" จึงค่อยเขียนไฟล์
```

**ควรได้:** unique index บน `(event_id, lower(email))` สำหรับ R1, unique บน `ticket_code` สำหรับ R5, `check` เบอร์ 10 หลักสำหรับ R3
**สัญญาณว่าผิดทาง:** ได้แค่ `create table` เปล่า ๆ ไม่มี index ไม่มี check → กติกายังไม่ได้ถูกบังคับที่ไหนเลย

### P2-3 · ตรวจ schema 4 ข้อ ★

**ใช้ตอน:** ทันทีหลังได้ `db/schema.sql` — อย่าข้าม

```text
ตรวจไฟล์ db/schema.sql ที่เพิ่งเขียน ตอบฉันเป็นตาราง 4 แถว

1. ไล่ทีละหน้าจอในไฟล์ requirements.md — หน้านั้นต้องแสดงอะไร ฟิลด์มีครบไหม
   ฟิลด์ส่วนตัวของฉันอยู่ในนั้นด้วยไหม
2. ชนิดข้อมูลของทุกคอลัมน์ถูกต้องไหม ข้อไหนที่ถ้าผิดแล้วแก้ทีหลังยาก ให้ชี้มา
3. ความสัมพันธ์ระหว่าง 2 ตารางถูกไหม เป็น one-to-many จริงหรือเปล่า
4. กติกา R1 ถึง R5 ข้อไหนบ้าง ที่ยังไม่มีอะไรบังคับในไฟล์นี้เลย

ห้ามแก้ไฟล์ในรอบนี้ รายงานอย่างเดียว
```

**จุดที่มักเจอ:** ข้อ 4 มักตอบว่า R2 (ที่นั่งเต็ม) ยังไม่มีอะไรบังคับ — นั่นคือของจริง ไปต่อที่ P2-4

### P2-4 · กันที่นั่งเกินที่ระดับฐานข้อมูล (R2)

```text
ตอนนี้กติกา R2 (ที่นั่งเต็มแล้วต้องปิดรับ) ยังบังคับได้แค่ในโค้ดฝั่งเซิร์ฟเวอร์

อธิบายให้ฉันฟังก่อนว่า ถ้ามีคน 5 คนกดปุ่มลงทะเบียนพร้อมกันตอนเหลือที่นั่งสุดท้าย 1 ที่
โค้ดที่ "นับก่อนแล้วค่อยบันทึก" จะเกิดอะไรขึ้น

ถ้าคำอธิบายของคุณตรงกับที่ฉันคิด ให้เพิ่ม trigger ลงในไฟล์ db/schema.sql
ที่กันที่นั่งเกินได้แม้มีคนกดพร้อมกัน พร้อมคอมเมนต์อธิบายเป็นภาษาไทย
ห้ามแก้ไฟล์อื่น
```

**ควรได้:** คำอธิบายเรื่อง race condition + trigger ที่ล็อกแถว `events` (`select ... for update`)
**สัญญาณว่าผิดทาง:** มันบอกว่า "ไม่น่ามีปัญหา เพราะเช็กก่อนแล้ว" → มันยังไม่เข้าใจ อย่าเพิ่งให้เขียนโค้ด

### P2-5 · ออกแบบสิทธิ์เข้าถึงฐานข้อมูล (RLS) ★

**ใช้ตอน:** ขั้นออกแบบ ไม่ใช่ไปโผล่ตอนบ่าย — ถ้าออกแบบผิดตั้งแต่ต้น หน้าแอดมินจะต้องรื้อ

```text
ออกแบบสิทธิ์เข้าถึงตาราง (Row Level Security) ของ Supabase สำหรับโปรเจกต์นี้

เป้าหมาย
- ใครก็อ่านรายละเอียดกิจกรรมในตาราง events ได้
- ห้ามใครอ่านหรือเขียนตาราง registrations จากฝั่งเบราว์เซอร์เลย แม้แต่การเพิ่มแถว
- การลงทะเบียนและหน้าแอดมิน จะเรียกผ่าน route handler ฝั่งเซิร์ฟเวอร์เท่านั้น

เขียนเป็นไฟล์ db/rls.sql พร้อมคอมเมนต์ภาษาไทยอธิบายทีละ policy
แล้วบอกฉันมาด้วยว่า ฉันจะตรวจเองยังไงว่ามันทำงานจริง โดยไม่ต้องเชื่อคำพูดคุณ
```

**ควรได้:** วิธีตรวจด้วย `curl` หรือหน้าต่างไม่ระบุตัวตน ยิงไปที่ REST ของ Supabase ตรง ๆ
**ทำไมต้องย้ำ:** AI มักตั้ง policy ให้เปิดกว้าง เพราะปิดแล้วโค้ดที่มันเขียน (อ่านจากเบราว์เซอร์) จะรันไม่ผ่าน
มันเลยเลือกทางที่ "ใช้งานได้" ไว้ก่อน ไม่ใช่ทางที่ปลอดภัย

### P2-6 · เขียน design.md

```text
เขียนไฟล์ design.md ที่รากโปรเจกต์ อธิบาย 3 อย่าง

1. เส้นทางของผู้เข้าร่วม ตั้งแต่เปิดหน้าแรกจนได้รหัสลงทะเบียน
2. เส้นทางของผู้ดูแล ตั้งแต่เปิด /admin จนกดเช็คอินได้ — ต้องเป็นคนละเส้นกับข้อ 1
3. ตารางว่ากติกา R1 ถึง R5 แต่ละข้อ ถูกบังคับที่ชั้นไหนบ้าง
   (เบราว์เซอร์ / เซิร์ฟเวอร์ / ฐานข้อมูล) — ข้อไหนที่มีแค่ชั้นเดียว ให้ทำตัวหนาไว้

ใช้ข้อความและตารางเท่านั้น ไม่ต้องวาดรูป ไม่ต้องเขียนโค้ด
```

**ควรได้:** ตารางที่ทำให้เห็นทันทีว่ากติกาข้อไหนยังบาง
**ประโยคที่ต้องจำจากสไลด์นี้:** *ชั้นเบราว์เซอร์คือความสะดวก ชั้นฐานข้อมูลคือความจริง*

### P2-7 · สร้าง AGENTS.md ★ ของที่ติดตัวโปรเจกต์ไปตลอด

```text
สร้างไฟล์ AGENTS.md ที่รากโปรเจกต์
เป็นกติกาที่ AI ทุกตัวที่มาทำงานในโปรเจกต์นี้ต้องทำตาม

ให้ครอบคลุม
- ไฟล์ที่ต้องอ่านก่อนเริ่มงานทุกครั้ง
- stack ที่ล็อกไว้ พร้อมเวอร์ชัน และข้อห้ามเพิ่ม library
- โครงไฟล์จริงของโปรเจกต์นี้ และกติกาการตั้งชื่อไฟล์กับโฟลเดอร์
- กติกา R1 ถึง R5 พร้อมระบุว่าแต่ละข้อบังคับที่ชั้นไหน
- กติกาเรื่องคีย์ลับและสิทธิ์เข้าถึงฐานข้อมูล
- ภาษาที่ใช้บนหน้าจอและในโค้ด
- สิ่งที่ห้ามทำ
- นิยามของคำว่า "งานเสร็จ"

เขียนเป็นข้อ ๆ สั้น ๆ อ่านแล้วทำตามได้ทันที ห้ามเขียนเป็นย่อหน้ายาว
```

**สกิล vs AGENTS.md:** สกิลคือ *สไตล์การทำงานของฉัน* ติดตัวเราไปทุกโปรเจกต์
`AGENTS.md` คือ *กติกาของโปรเจกต์นี้* ใครเปิดโฟลเดอร์นี้ก็ต้องเล่นตามกติกานี้
**เครื่องมืออื่น:** ถ้าใช้ Claude Code ให้สร้างไฟล์ `CLAUDE.md` ที่มีบรรทัดเดียวว่า `@AGENTS.md`

### P2-8 · ให้ AI ตรวจ AGENTS.md ของตัวเอง

**ใช้ตอน:** หลังเขียน `AGENTS.md` เสร็จ — ใช้เวลา 2 นาที คุ้มมาก

```text
อ่านไฟล์ AGENTS.md ที่เพิ่งเขียน แล้วตอบฉัน 2 ข้อ

1. มีข้อไหนบ้างที่เขียนกำกวมจนคุณตีความได้หลายทาง ยกตัวอย่างการตีความที่ต่างกันมาให้ดู
2. ถ้าฉันสั่งงานที่ขัดกับกติกาในไฟล์นี้ คุณจะทำอะไร — ตอบเป็นประโยคเดียว

ห้ามแก้ไฟล์
```

**คำตอบที่ถูกของข้อ 2:** "จะหยุดแล้วถามคุณก่อน ไม่เลือกข้างเอง"
**ถ้าตอบว่า "จะทำตามที่คุณสั่ง":** ให้เพิ่มบรรทัดนั้นลงใน `AGENTS.md` ชัด ๆ
