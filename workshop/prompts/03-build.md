### P3-1 · งานที่ 1 — เชื่อมฐานข้อมูล

```text
เชื่อมโปรเจกต์กับ Supabase สร้าง 3 ไฟล์นี้

1. src/lib/supabase.ts
   client ฝั่งสาธารณะ อ่านค่าจาก NEXT_PUBLIC_SUPABASE_URL และ NEXT_PUBLIC_SUPABASE_ANON_KEY
   สร้างแบบ lazy คือสร้างตอนถูกเรียกใช้ ไม่ใช่ตอน import

2. src/lib/supabaseServer.ts
   client ฝั่งเซิร์ฟเวอร์ อ่านค่าจาก SUPABASE_SERVICE_ROLE_KEY
   ใส่คอมเมนต์เตือนไว้ว่าห้าม import ไฟล์นี้จากไฟล์ที่มี "use client"

3. .env.example
   มีชื่อตัวแปรครบทุกตัวแต่ไม่ใส่ค่าจริง พร้อมคอมเมนต์ว่าตัวไหน public ตัวไหนลับ

ถ้าตัวแปรไม่ครบ ให้ throw error ที่อ่านรู้เรื่องเป็นภาษาไทย
ห้ามใส่ค่า placeholder ปลอมแทน เพราะจะทำให้เว็บเงียบ ๆ ไม่มีข้อมูลโดยไม่มี error ให้เห็น

แตะได้แค่ 3 ไฟล์นี้ ห้ามแตะไฟล์อื่น
```

**ทำไมห้าม placeholder:** ถ้าใส่ `https://placeholder.supabase.co` ไว้ พอลืมตั้ง env ตอน deploy
เว็บจะขึ้นหน้าเปล่าโดยไม่มี error ให้จับ — เสียเวลาหาเป็นชั่วโมง

### P3-2 · งานที่ 2 — ชั้นข้อมูลและชั้นตรวจ

```text
สร้าง 3 ไฟล์นี้ ห้ามแตะไฟล์อื่น

1. src/lib/types.ts
   ชนิดข้อมูลของ 2 ตารางให้ตรงกับ db/schema.sql เป๊ะ
   และรายการรหัส error พร้อมข้อความภาษาไทยของแต่ละรหัส

2. src/lib/validate.ts
   - normalizeEmail : ตัดช่องว่างหัวท้าย และแปลงเป็นตัวพิมพ์เล็ก
   - isValidEmail, isValidPhone (10 หลักพอดี)
   - validateRegistration : ตรวจตามกติกา R3 คืนรหัส error ตัวแรกที่เจอ
   - generateTicketCode : สุ่มรหัสลงทะเบียน

3. src/lib/db.ts
   ฟังก์ชันที่คุยกับฐานข้อมูลทั้งหมด — อ่านกิจกรรมล่าสุด นับที่นั่ง ตรวจอีเมลซ้ำ
   เพิ่มผู้ลงทะเบียน อ่านรายชื่อ อัปเดตสถานะเช็คอิน

กติกา
- ห้ามใช้ any ที่ไหนเลย
- ข้อความที่ผู้ใช้จะเห็น เป็นภาษาไทยทั้งหมด
- ตั้งแต่นี้ไป ไฟล์อื่นทั้งโปรเจกต์ต้องเรียกฐานข้อมูลผ่าน db.ts เท่านั้น

เสร็จแล้วรัน npx tsc --noEmit แล้วรายงานผลจริงให้ฉันดู
```

### P3-3 · งานที่ 3 — หน้าแรก

```text
แก้ไฟล์ src/app/page.tsx ให้เป็นหน้าแรกของระบบ

- เป็น Server Component
- เรียก getCurrentEvent() และ getSeatsLeft() จาก @/lib/db เท่านั้น ห้ามเรียก supabase ตรง ๆ
- แสดง ชื่องาน รายละเอียด วันเวลา (locale th-TH) สถานที่ ที่นั่งทั้งหมด และที่นั่งคงเหลือ
- ถ้าที่นั่งเหลือมากกว่า 0 ให้แสดงปุ่มไปหน้า /register พร้อมส่ง eventId ไปด้วย
- ถ้าเต็มแล้ว ให้แสดงข้อความ "ที่นั่งเต็มแล้ว" แทนปุ่ม (กติกา R2)
- ถ้ายังไม่มีกิจกรรมในฐานข้อมูล ให้แสดงข้อความบอกว่าต้องรันไฟล์ SQL ก่อน
- ที่นั่งคงเหลือต้องเป็นค่าสด ห้ามให้ Next แคชหน้านี้

แตะได้แค่ไฟล์ src/app/page.tsx ไฟล์เดียว
```

**ทดสอบทันที:** เปิด `http://localhost:3000` ต้องเห็นชื่องานของตัวเอง แล้ว `git commit`

### P3-4 · งานที่ 4 — ฟอร์มลงทะเบียน + ตรวจข้อมูล (R3)

```text
แก้ไฟล์ src/app/register/page.tsx ให้เป็นฟอร์มลงทะเบียน

ช่องกรอก
- ชื่อ-นามสกุล (บังคับ)
- อีเมล (บังคับ)
- เบอร์โทรศัพท์ (บังคับ)
- คณะ/หน่วยงาน (ไม่บังคับ)
- [ฟิลด์ส่วนตัวของฉัน]

กติกา
- ตรวจตาม R3 โดยเรียกฟังก์ชันจาก @/lib/validate ห้ามเขียน regex ซ้ำในไฟล์นี้
- มี checkbox ยินยอมให้เก็บข้อมูลส่วนบุคคล ที่ไม่ติ๊กไว้ล่วงหน้า ไม่ติ๊กแล้วส่งไม่ได้
  พร้อมข้อความบอกว่าเก็บข้อมูลไปทำอะไร เก็บนานแค่ไหน และใครเห็นได้บ้าง
- ข้อความ error ทุกอันเป็นภาษาไทย
- รอบนี้ยังไม่ต้องบันทึกลงฐานข้อมูล กดส่งแล้วให้ขึ้นข้อความว่าผ่านการตรวจแล้วพอ

แตะได้แค่ไฟล์ src/app/register/page.tsx ไฟล์เดียว
```

**✔ Checkpoint หลังงานที่ 4 — ฟอร์มต้องเด้ง error ได้**
- [ ] กดส่งโดยเว้นช่องว่าง → ขึ้นข้อความเตือน
- [ ] อีเมลไม่มี `@` → ไม่ผ่าน
- [ ] เบอร์ 9 หลัก → ไม่ผ่าน
- [ ] ไม่ติ๊กช่องยินยอม → ไม่ผ่าน
- [ ] ยังไม่มีแถวใหม่ในฐานข้อมูล

ผ่านแล้ว **commit ทันที** แล้วปักธงเขียว

### P3-5 · งานที่ 5 — บันทึกลงฐานข้อมูล + ออกรหัส (R1 R2 R5)

```text
ทำให้ฟอร์มบันทึกลงฐานข้อมูลได้จริง แก้ 2 ไฟล์

1. สร้าง src/app/api/register/route.ts รับ POST
   - ตรวจข้อมูลซ้ำที่เซิร์ฟเวอร์ ด้วยฟังก์ชันชุดเดียวกับที่หน้าจอใช้ (R3)
     เพราะคนอาจปิด JavaScript หรือยิง API ตรง ๆ
   - ตรวจอีเมลซ้ำในกิจกรรมเดียวกัน แบบไม่สนตัวพิมพ์เล็ก-ใหญ่ (R1)
   - ตรวจที่นั่งเต็ม โดย "เต็ม" คือ จำนวนที่ลงแล้ว >= capacity (R2)
   - ออกรหัสลงทะเบียน ถ้าสุ่มชนกับของเดิมให้สุ่มใหม่ ไม่ใช่ล้มเหลว (R5)
   - ★ ข้อความ error ของ "อีเมลซ้ำ" กับ "รหัสลงทะเบียนชน" ต้องไม่ใช่ข้อความเดียวกัน
     ทั้งที่ทั้งคู่มาจาก error 23505 ของ Postgres เหมือนกัน

2. แก้ src/app/register/page.tsx ให้ยิงไปที่ /api/register
   แสดงรหัสลงทะเบียนเมื่อสำเร็จ และกันการกดปุ่มซ้ำระหว่างรอผลลัพธ์

แตะได้แค่ 2 ไฟล์นี้
เสร็จแล้วรัน npx tsc --noEmit แล้วรายงานผลจริง
```

**จุดที่ทุกคนพลาด:** แปลง error `23505` เป็นข้อความเดียวรวด ทำให้ตอนรหัสชน ผู้ใช้เห็นว่า "อีเมลซ้ำ"

### P3-6 · งานที่ 6 — หน้าแอดมิน + รหัสผ่าน (R4)

```text
ทำหน้าแอดมินและระบบเข้าสู่ระบบ สร้าง/แก้ 5 ไฟล์

1. src/lib/adminAuth.ts
   ตรวจรหัสผ่านจากตัวแปร ADMIN_PASSWORD และสร้าง/ตรวจคุกกี้ session
2. src/app/api/admin/login/route.ts
   ตรวจรหัสผ่านที่เซิร์ฟเวอร์ ผ่านแล้วตั้งคุกกี้แบบ httpOnly
3. src/app/api/admin/registrations/route.ts
   GET รายชื่อผู้ลงทะเบียน ถ้าไม่มีคุกกี้ต้องตอบ 401 และต้องไม่มีข้อมูลหลุดออกไปเลย
4. src/app/api/admin/checkin/route.ts
   POST สลับสถานะเช็คอิน ถ้าไม่มีคุกกี้ต้องตอบ 401
5. src/app/admin/page.tsx
   ตารางผู้ลงทะเบียน เรียกข้อมูลผ่าน API ทั้งหมด ห้ามเรียก supabase ตรง ๆ

ข้อห้ามสำคัญที่สุด
- รหัสผ่านต้องไม่ปรากฏในไฟล์ที่มี "use client" เด็ดขาด
- ห้ามแสดงรหัสผ่านตัวอย่างบนหน้าจอ

ทำเสร็จให้บอกฉันว่า ฉันจะตรวจเองยังไงว่ารหัสผ่านไม่หลุดไปฝั่งเบราว์เซอร์
```

**✔ Checkpoint หลังงานที่ 6 — กรอกฟอร์มแล้วชื่อต้องขึ้นหน้าแอดมิน**
- [ ] กรอกฟอร์มครบ → ได้รหัสลงทะเบียน
- [ ] เปิดหน้าแอดมิน ใส่รหัสผ่าน → เห็นชื่อที่เพิ่งกรอก
- [ ] เปิด `/admin` ในหน้าต่างใหม่โดยไม่ใส่รหัส → ไม่เห็นอะไรเลย
- [ ] เปิด View Source แล้วค้นหารหัสผ่านของตัวเอง → หาไม่เจอ

### P3-8 · ขอข้อความ commit

**ใช้ตอน:** จบทุกงาน ก่อนสั่งงานถัดไป

```text
สรุปสิ่งที่เพิ่งทำเสร็จเป็นข้อความ commit ภาษาอังกฤษ 1 บรรทัด ไม่เกิน 72 ตัวอักษร
แล้วบอกฉันว่ามีไฟล์อะไรบ้างที่เปลี่ยนไป

ห้ามรัน git commit เอง ฉันจะรันเอง
```

**ทำไมห้ามให้มัน commit เอง:** วันนี้เราต้องรู้ให้ได้ว่าจุดเซฟอยู่ตรงไหนบ้าง
ถ้ามัน commit ให้เงียบ ๆ เราจะไม่รู้ว่าย้อนกลับไปจุดไหนได้

### P3-9 · เมื่อ agent เดินผิดทางกลางงาน

**ใช้ตอน:** เห็นว่ามันเริ่มแก้ไฟล์ที่ไม่ได้สั่ง — กด `Esc` ก่อน แล้วพิมพ์อันนี้

```text
หยุดก่อน อย่าแก้อะไรเพิ่ม

บอกฉันมาเป็นรายการว่า ตั้งแต่คำสั่งล่าสุด คุณแก้ไฟล์อะไรไปแล้วบ้าง และแก้อะไรในแต่ละไฟล์
ไฟล์ไหนที่ไม่ได้อยู่ในขอบเขตที่ฉันสั่ง ให้บอกฉันด้วย

ห้ามแก้อะไรเพิ่มจนกว่าฉันจะสั่ง
```

**แล้วทำต่อยังไง:** ถ้ามันแตะไฟล์นอกขอบเขต → `git restore <ไฟล์นั้น>` แล้วสั่งใหม่ด้วยขอบเขตที่แคบลง
ถ้าเสียหายหนักจนไม่รู้ว่าพังตรงไหน → ย้อน commit ล่าสุด (ดู **P5-5**) อย่าพยายามแก้ต่อบนกองที่พังอยู่
