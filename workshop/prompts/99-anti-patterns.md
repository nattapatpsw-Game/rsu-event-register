# ✕ prompt ที่ห้ามใช้ — 8 คู่เทียบ

> อ่านคู่กับสไลด์ "จาก 'อยากได้เว็บ' ไปเป็นสิ่งที่ AI ทำงานต่อได้"
> ทุกคู่คือเรื่องเดียวกัน สั่งคนละแบบ ได้ผลคนละอย่าง

---

### คู่ที่ 1 — เริ่มโปรเจกต์

**✕ สั่งแบบนี้**

```text
ทำเว็บลงทะเบียนให้หน่อย
```

ได้หน้าสวย ๆ มา 1 หน้า · ไม่มีฐานข้อมูล กรอกแล้วข้อมูลหาย · ไม่มีหน้าแอดมิน ·
ถามใหม่อีกรอบได้คนละแบบกับรอบแรก · สุดท้ายต้องรื้อทำใหม่

**✓ สั่งแบบนี้**

```text
ฉันอยากทำระบบลงทะเบียนกิจกรรมสำหรับงาน [ชื่องานของฉัน]
อย่าเพิ่งเขียนโค้ด ถามฉัน 5 คำถามที่จำเป็นที่สุดก่อน ทีละคำถาม
เมื่อได้คำตอบครบแล้วค่อยสรุปเป็นสเปกลงไฟล์ requirements.md
```

---

### คู่ที่ 2 — ขอบเขตของงาน

**✕ สั่งแบบนี้**

```text
แก้หน้าลงทะเบียนหน่อย
```

มันเดาเองว่า "หน้าลงทะเบียน" คือไฟล์ไหน แล้วมักจะแถมแก้ไฟล์อื่นให้ด้วย
ที่เจ็บที่สุดคือมันลบโค้ดที่หน้าอื่นเรียกใช้อยู่ แล้วหน้านั้นหายไปเงียบ ๆ

**✓ สั่งแบบนี้**

```text
แก้ไฟล์ src/app/register/page.tsx เท่านั้น
เปลี่ยนข้อความ error ตอนเบอร์โทรไม่ครบ 10 หลัก ให้บอกด้วยว่ากรอกมากี่หลัก
แตะได้แค่ไฟล์นี้ ห้ามแตะไฟล์อื่น
```

---

### คู่ที่ 3 — ตอนเจอ error

**✕ สั่งแบบนี้**

```text
มัน error แก้ให้หน่อย
```

มันจะเดาว่า error คืออะไร แล้วแก้จุดที่ไม่ใช่ต้นเหตุ —
บ่อยครั้งแก้จน error หายแต่พฤติกรรมยังผิดอยู่

**✓ สั่งแบบนี้**

```text
ข้อความ error เต็ม ๆ: [วางทั้งก้อน]
ฉันคาดว่าจะเกิด: [สิ่งที่ควรเป็น]
สิ่งที่เกิดขึ้นจริง: [สิ่งที่เห็น]
ลองแก้ไปแล้ว: [หรือ ยังไม่ได้ลองอะไรเลย]
อย่าเพิ่งแก้โค้ด อธิบายสาเหตุให้ฉันฟังก่อน
```

---

### คู่ที่ 4 — ทำหลายอย่างพร้อมกัน

**✕ สั่งแบบนี้**

```text
ทำระบบลงทะเบียนให้ครบเลย มีหน้าแรก หน้าฟอร์ม หน้าแอดมิน
เชื่อมฐานข้อมูล ตรวจข้อมูล ออกรหัส ส่งออก CSV ด้วย
```

ได้โค้ดก้อนใหญ่ที่พังแล้วไม่รู้ว่าพังตรงไหน ย้อนกลับก็ไม่ได้เพราะไม่มีจุดเซฟระหว่างทาง

**✓ สั่งแบบนี้**

```text
รอบนี้ทำงานเดียว: สร้าง src/app/api/register/route.ts รับ POST
บันทึกผู้ลงทะเบียนลงฐานข้อมูล และออกรหัสลงทะเบียนที่ไม่ซ้ำ
แตะได้แค่ไฟล์นี้ เสร็จแล้วรัน npx tsc --noEmit แล้วรายงานผลจริง
แล้วเสนอข้อความ commit มาให้ฉัน
```

---

### คู่ที่ 5 — ปล่อยให้เลือก stack เอง

**✕ สั่งแบบนี้**

```text
ใช้อะไรดีที่สุดสำหรับงานนี้ เลือกให้หน่อย
```

เปิดแชทใหม่รอบหน้ามันจะเสนอของใหม่ — เช้า Next.js บ่าย Vite เย็น Express
แล้วโค้ดสามกองจะต่อกันไม่ติด

**✓ สั่งแบบนี้**

```text
โปรเจกต์นี้ใช้ Next.js 16 (App Router) + Supabase เท่านั้น deploy บน Vercel
ห้ามเปลี่ยน framework ห้ามเพิ่ม library ใหม่โดยไม่ถามฉันก่อน
ถ้าคิดว่ามีทางที่ดีกว่า ให้บอกฉัน แต่อย่าเปลี่ยนเอง
```

แล้ว**เขียนลงไฟล์ `AGENTS.md`** ด้วย — พูดในแชทอย่างเดียวไม่พอ

---

### คู่ที่ 6 — เรื่องความปลอดภัย

**✕ สั่งแบบนี้**

```text
มัน error ว่าไม่มีสิทธิ์อ่านตาราง ทำให้มันรันผ่านหน่อย
```

มันจะเปิด policy ให้ใครก็อ่านตารางผู้ลงทะเบียนได้ — โค้ดรันผ่านทันที
แต่ชื่อ อีเมล เบอร์โทรของทั้งห้องเปิดให้คนทั้งอินเทอร์เน็ตอ่าน

**✓ สั่งแบบนี้**

```text
ตอนนี้ติดสิทธิ์อ่านตาราง registrations
อธิบายให้ฉันฟังก่อนว่าติดเพราะอะไร และมีทางแก้กี่ทาง
ทางไหนที่ไม่ต้องเปิดสิทธิ์ให้คนนอกอ่านตารางนี้บ้าง
ห้ามแก้ policy เอง ห้ามปิด RLS
```

---

### คู่ที่ 7 — ตอนให้ AI เขียน test

**✕ สั่งแบบนี้**

```text
เขียน test ให้โปรเจกต์นี้หน่อย
```

มันจะอ่านโค้ดที่ตัวเองเพิ่งเขียน แล้วเขียน test ให้ผ่าน — ไม่ได้เขียนเพื่อจับผิด
ผลคือได้ test สีเขียวเต็มจอทั้งที่บั๊กยังอยู่ครบ

**✓ สั่งแบบนี้**

```text
เขียน test จากไฟล์ requirements.md เท่านั้น ห้ามอ่านโค้ดที่เขียนไว้แล้ว
ครอบคลุมกติกา R1 ถึง R5 ให้ครบทุกข้อ
ถ้าสเปกข้อไหนกำกวมจนเขียน test ไม่ได้ ให้ถามฉัน อย่าเดาเอง
```

---

### คู่ที่ 8 — ตอนมันบอกว่าเสร็จแล้ว

**✕ เชื่อแบบนี้**

```text
(AI ตอบ) เรียบร้อยครับ ระบบทำงานได้แล้ว
```

"น่าจะใช้ได้แล้ว" ไม่ใช่หลักฐาน — บ่อยมากที่มันไม่ได้รันอะไรเลย

**✓ ถามกลับแบบนี้**

```text
คุณรันคำสั่งอะไรไปบ้าง แสดงผลลัพธ์จริงที่ได้ให้ฉันดู
- npx tsc --noEmit ผลเป็นยังไง
- npm run lint ผลเป็นยังไง
- npm run build ผ่านไหม

ถ้ายังไม่ได้รัน ให้บอกตรง ๆ ว่ายังไม่ได้รัน อย่าเดาผลลัพธ์
```

---

## สรุปเป็นประโยคเดียว

> **prompt ที่ดีไม่ใช่ prompt ที่ยาว แต่คือ prompt ที่บอก 3 อย่าง:**
> **แตะไฟล์ไหนได้บ้าง · ผลลัพธ์ที่ถูกต้องหน้าตายังไง · และห้ามทำอะไร**
