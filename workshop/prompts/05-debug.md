### P5-1 · สูตรส่ง error ให้ AI — 4 บรรทัด ★ ใช้บ่อยที่สุดของขั้นนี้

**ใช้ตอน:** เจอ error อะไรก็ตาม ก่อนชูธงแดงให้ลองอันนี้ก่อนเสมอ

```text
ข้อความ error เต็ม ๆ:
[วางทั้งก้อน อย่าตัด อย่าสรุปเอง]

ฉันคาดว่าจะเกิด:
[สิ่งที่ควรจะเป็น]

สิ่งที่เกิดขึ้นจริง:
[สิ่งที่เห็นบนหน้าจอ]

ลองแก้ไปแล้ว:
[ถ้ายังไม่ได้ลอง ให้เขียนว่า ยังไม่ได้ลองอะไรเลย]

อย่าเพิ่งแก้โค้ด อธิบายสาเหตุให้ฉันฟังก่อน
```

**ทำไมแต่ละบรรทัดสำคัญ**

- **ข้อความ error เต็ม ๆ** — บรรทัดที่เราคิดว่าไม่สำคัญ มักเป็นบรรทัดที่บอกชื่อไฟล์และเลขบรรทัด
- **คาดว่าจะเกิด / เกิดจริง** — สองบรรทัดนี้ทำให้ AI รู้ว่าอะไรคือ "ถูก" ไม่งั้นมันจะแก้ให้ error หายแต่พฤติกรรมยังผิด
- **ลองแก้ไปแล้ว** — กันไม่ให้มันเสนอทางเดิมที่เราลองแล้วซ้ำอีกรอบ
- **อย่าเพิ่งแก้โค้ด** — บรรทัดที่ประหยัดเวลามากที่สุดของทั้งวัน

### P5-2 · ให้อธิบายก่อน ห้ามแก้ ★

**ใช้ตอน:** ทุกครั้งที่ยังไม่เข้าใจว่าทำไมมันพัง

```text
อธิบายสาเหตุที่แท้จริงให้ฉันฟังก่อน ห้ามแก้โค้ด

บอกมาว่า
1. โค้ดบรรทัดไหนเป็นต้นเหตุ (ระบุชื่อไฟล์และเลขบรรทัด)
2. ทำไมบรรทัดนั้นถึงทำให้เกิดอาการที่ฉันเห็น
3. ถ้าแก้แล้วจะกระทบอะไรอีกบ้าง

ถ้าคุณยังไม่แน่ใจ ให้บอกว่าไม่แน่ใจ แล้วบอกว่าต้องการข้อมูลอะไรเพิ่ม
```

**ประโยคที่ต้องพูดบนเวที:** *ถ้ามันอธิบายไม่ได้ แปลว่ามันกำลังเดา — และเดาต่ออีกกี่รอบก็ไม่เจอ*

### P5-3 · แทรกบั๊ก B1 — ตรวจอีเมลซ้ำแบบ case-sensitive

```text
ในไฟล์ src/lib/validate.ts ให้แก้ฟังก์ชัน normalizeEmail
ให้ตัดเฉพาะช่องว่างหัวท้าย ไม่ต้องแปลงเป็นตัวพิมพ์เล็ก

แก้เฉพาะบรรทัดนั้นบรรทัดเดียว ห้ามแตะไฟล์อื่น และห้ามอธิบายอะไรเพิ่ม
```

**ตรวจว่าแทรกสำเร็จ:** ลงทะเบียน `test@rsu.ac.th` แล้วลงซ้ำด้วย `TEST@rsu.ac.th`
**สิ่งที่จะเกิดขึ้นจริง:** ฐานข้อมูลจะดักไว้ด้วย unique index `(event_id, lower(email))` —
**นี่คือบทเรียน ไม่ใช่ความผิดพลาด** ให้สอนว่า "ถ้าไม่ได้ใส่ index ไว้ตั้งแต่ขั้นออกแบบ วันนี้ข้อมูลจะซ้ำจริง"
อยากให้พังเต็ม ๆ ให้รัน `drop index if exists registrations_event_email_unique;` แล้วรัน `db/schema.sql` ใหม่เพื่อเอากลับคืน

### P5-4 · แทรกบั๊ก B2 — ที่นั่งเต็มแล้วยังลงได้อีกคน

```text
ในไฟล์ src/lib/db.ts ฟังก์ชัน createRegistration
ตรงเงื่อนไขที่ตรวจจำนวนที่นั่ง ให้เปลี่ยนจาก >= เป็น >

แก้เฉพาะตัวดำเนินการนั้นตัวเดียว ห้ามแตะที่อื่น
```

**ตรวจว่าแทรกสำเร็จ:** ตั้ง `capacity` = 3 แล้วลงทะเบียน 4 คน
**สิ่งที่จะเกิดขึ้นจริง:** trigger `enforce_capacity()` จะดักคนที่ 4 ไว้
อยากให้พังเต็ม ๆ ให้รัน `drop trigger if exists trg_enforce_capacity on public.registrations;`

### P5-5 · แทรกบั๊ก B3 — หน้าแอดมินขาวทั้งหน้า

```text
ในไฟล์ src/app/admin/page.tsx ในตารางผู้ลงทะเบียน
ช่องที่แสดงฟิลด์ส่วนตัวของฉัน (ตอนนี้คือ row.shirt_size)
ให้เปลี่ยนเป็น row.shirt_size.toUpperCase()

แก้เฉพาะบรรทัดนั้น ห้ามใส่การตรวจค่าว่าง ห้ามแตะไฟล์อื่น
```

**ตรวจว่าแทรกสำเร็จ:** ใส่แถวที่ฟิลด์ส่วนตัวเป็น `null` แล้วเปิด `/admin`

```sql
update registrations set shirt_size = null
where ticket_code = (select ticket_code from registrations limit 1);
```

**Console จะขึ้น:** `TypeError: Cannot read properties of null (reading 'toUpperCase')`
**ทางแก้ที่ถูก:** `{row.shirt_size?.toUpperCase() ?? "-"}`
**ประเด็นที่ต้องย้ำ:** ค่าที่ "ไม่บังคับกรอก" ในฐานข้อมูล คือค่าที่จะเป็น `null` ได้เสมอ —
โค้ดที่ AI เขียนมักลืมข้อนี้ เพราะมันเห็นแต่ข้อมูลตัวอย่างที่กรอกครบ

### P5-6 · เมื่อ AI แก้วนไม่จบ — กฎ 3 ครั้ง

**ใช้ตอน:** แก้เรื่องเดิม 3 รอบแล้วยังไม่หาย → **หยุด** อย่าแก้รอบที่ 4

```text
เราแก้เรื่องนี้มา 3 รอบแล้วยังไม่หาย หยุดแก้ก่อน

1. สรุปให้ฉันฟังว่า 3 รอบที่ผ่านมาคุณลองอะไรไปบ้าง และแต่ละรอบผลเป็นยังไง
2. บอกมาว่าสมมติฐานไหนที่คุณคิดว่าถูก แต่จริง ๆ อาจจะผิด
3. ถ้าจะหาสาเหตุที่แท้จริง ต้องการข้อมูลอะไรเพิ่มจากฉันบ้าง

ห้ามแก้โค้ดในรอบนี้
```

**ถ้ายังไม่ได้:** ย้อน commit (P5-7) แล้วเริ่มใหม่ด้วยคำสั่งที่แคบกว่าเดิม

### P5-7 · ย้อนกลับ commit ล่าสุด

**ใช้ตอน:** ของเสียหายหนัก หรือไม่รู้แล้วว่าพังตรงไหน — **อย่าพยายามแก้ต่อบนกองที่พังอยู่**

```text
แสดง git log --oneline ให้ฉันดู 10 รายการล่าสุด
แล้วบอกว่าแต่ละ commit ทำอะไร

อย่าเพิ่งรันคำสั่ง git ใด ๆ ที่เปลี่ยนโค้ด ฉันจะเลือกเอง
```

จากนั้นรันเอง:

```bash
git restore .                   # ทิ้งการแก้ที่ยังไม่ commit ทั้งหมด
git restore src/app/admin/page.tsx   # ทิ้งเฉพาะไฟล์เดียว
git reset --hard <commit id>    # ย้อนกลับไปจุดเซฟที่เลือก
```

**ยอมเสียงาน 15 นาที ดีกว่าเสียทั้งบ่าย**

### P5-8 · ตัดขอบเขตให้แคบลง เมื่อ agent เดินผิดทาง

**ใช้ตอน:** สั่งกว้าง ๆ แล้วมันไปแก้ผิดที่

```text
เลิกใช้คำสั่งเดิม เริ่มใหม่ด้วยขอบเขตที่แคบลง

งานรอบนี้: แก้เฉพาะไฟล์ [ชื่อไฟล์เต็ม]
บรรทัดที่เกี่ยวข้อง: [เลขบรรทัด หรือชื่อฟังก์ชัน]
สิ่งที่ต้องเปลี่ยน: [อธิบายผลลัพธ์ที่ต้องการ ไม่ใช่วิธีทำ]

ห้ามแตะไฟล์อื่น ห้ามจัดรูปแบบโค้ดใหม่ ห้ามเปลี่ยนชื่อตัวแปรที่ไม่เกี่ยวข้อง
ก่อนแก้ ให้บอกฉันก่อนว่าจะเปลี่ยนอะไรบ้าง
```

**เลิกพูดว่า** "แก้หน้านั้นหน่อย" → **เปลี่ยนเป็น** ชื่อไฟล์ บรรทัด และสิ่งที่ต้องเกิดขึ้น

## บั๊กที่ AI ทำบ่อย 4 แบบ — และวิธีกัน

| | อาการ | วิธีกัน |
|---|---|---|
| **1** | เรียก API หรือฟังก์ชันที่ไม่มีอยู่จริง (`is not a function`) | ถามว่า "ฟังก์ชันนี้มีจริงไหม อ้างอิงจากไหน" หรือให้เปิดเอกสารจริง |
| **2** | ลบโค้ดที่ยังใช้อยู่ หน้าอื่นหายไปเงียบ ๆ | commit ก่อนทุกงาน + ระบุขอบเขตไฟล์ทุกคำสั่ง |
| **3** | ค่า `null` ไม่ถูกป้องกัน (บั๊ก B3) | ฟิลด์ที่ไม่บังคับกรอก ต้องมี `?.` และ `??` เสมอ |
| **4** | แก้ให้ error หาย แต่พฤติกรรมยังผิด | บอก "คาดว่าจะเกิด / เกิดจริง" ทุกครั้ง ไม่ใช่แค่แปะ error |
