# P4 ขั้นทดสอบ

> หลักการเดียวของขั้นนี้: **เอากติกา R1–R5 ที่เขียนไว้ตอนเช้า มาทำเป็นกรณีทดสอบ**
> ไม่มีอะไรใหม่เลย ทุกอย่างลอกมาจาก `requirements.md`

---

### P4-1 · ให้ agent เขียน test โดยล็อกแหล่งข้อมูล ★

**ใช้ตอน:** เริ่มขั้นทดสอบ

```text
เขียน test จากไฟล์ requirements.md เท่านั้น ห้ามอ่านโค้ดที่เขียนไว้แล้ว
ครอบคลุมกติกา R1 ถึง R5 ให้ครบทุกข้อ

ถ้าสเปกข้อไหนกำกวมจนเขียน test ไม่ได้ ให้ถามฉัน อย่าเดาเอง
ถ้าต้องติดตั้ง library เพิ่ม ให้บอกฉันก่อน อย่าเพิ่งติดตั้งเอง

บอกฉันมาก่อนว่าจะเขียน test กี่ข้อ แต่ละข้อทดสอบกติกาข้อไหน แล้วรอฉันอนุมัติ
```

**กับดักที่ต้องเตือนตรง ๆ:** test ที่ AI เขียนเองจากโค้ดของตัวเอง **มักจะผ่านหมด**
เพราะมันเขียนให้ผ่าน ไม่ได้เขียนเพื่อจับผิด — การล็อกให้อ่านแค่สเปกคือสิ่งที่กันเรื่องนี้
**สัญญาณว่าผิดทาง:** มันเริ่มเปิดไฟล์ `src/lib/db.ts` → หยุด แล้วย้ำว่า "อ่านแค่ requirements.md"

### P4-2 · ตรวจว่า test จับบั๊กได้จริงไหม ★

**ใช้ตอน:** หลังเขียน test เสร็จ และหลังแทรกบั๊กแล้ว

```text
ตอนนี้ในโค้ดมีบั๊กอยู่ 3 ตัวที่ฉันแทรกไว้เอง
รัน test ทั้งหมด แล้วรายงานผลจริง ห้ามแก้โค้ดและห้ามแก้ test

ถ้า test ผ่านหมดทั้งที่ยังมีบั๊กอยู่ ให้บอกฉันว่า test ข้อไหนควรจับได้แต่จับไม่ได้
และอธิบายว่าทำไมมันถึงหลุด
```

**ประโยคที่ต้องพูดบนเวที:** *ถ้า test ผ่านทั้งที่บั๊กยังอยู่ แปลว่า test ใช้ไม่ได้ ไม่ใช่โค้ดถูก*

### P4-3 · ตรวจสิทธิ์เข้าถึงฐานข้อมูลก่อนปิดงาน ★

**ใช้ตอน:** ขั้นทดสอบ และย้ำอีกครั้งก่อน deploy

```text
ตรวจสิทธิ์เข้าถึงตารางในฐานข้อมูลของโปรเจกต์นี้ให้ฉัน
บอกมาว่าตอนนี้ใครอ่านหรือเขียนตารางไหนได้บ้าง แล้วเสนอกฎที่ปลอดภัยกว่า

อย่าเพิ่งแก้อะไร และบอกฉันมาด้วยว่าจะตรวจด้วยตัวเองยังไง
โดยไม่ต้องเชื่อคำพูดคุณ — ขอเป็นคำสั่งที่ฉันรันเองได้
```

**ทำเองหลังจากนั้น** (นี่คือของจริง อย่าเชื่อ agent อย่างเดียว):

```bash
curl "https://<project>.supabase.co/rest/v1/registrations?select=*" -H "apikey: <anon-key>"
```

- ได้ `[]` หรือ error เรื่องสิทธิ์ = **ผ่าน**
- ได้รายชื่อ อีเมล เบอร์โทรของทั้งห้องกลับมา = **ยังเปิดกว้างอยู่ ต้องแก้ก่อน deploy**

---

### P4-4 · ตรวจว่าคีย์ลับหลุดไปฝั่งเบราว์เซอร์หรือยัง

**ใช้ตอน:** ก่อนปิดขั้นทดสอบ

```text
ค้นทั้งโปรเจกต์ให้ฉัน แล้วตอบเป็นรายการ

1. มีไฟล์ไหนบ้างที่ขึ้นต้นด้วย "use client" แล้ว import supabaseServer หรืออ่าน
   SUPABASE_SERVICE_ROLE_KEY / ADMIN_PASSWORD / ADMIN_SESSION_SECRET
2. มีที่ไหนบ้างที่เขียนรหัสผ่านหรือคีย์ไว้ตรง ๆ ในโค้ด
3. มีที่ไหนบ้างที่ console.log ชื่อ อีเมล หรือเบอร์โทรของผู้ลงทะเบียน

รายงานอย่างเดียว ห้ามแก้
```

**ตรวจซ้ำด้วยตาตัวเอง:** `npm run build` แล้วค้นคำว่า `service_role` ในโฟลเดอร์ `.next/static/` — ต้องหาไม่เจอ

### P4-5 · ตรวจว่าฟิลด์ส่วนตัวอยู่ครบ 4 ที่

**ใช้ตอน:** ก่อนปิดขั้นทดสอบ — ข้อที่คนลืมบ่อยที่สุด

```text
ฟิลด์ส่วนตัวของฉันคือ [ชื่อฟิลด์]
ตรวจให้ฉันว่ามันมีครบทั้ง 4 ที่หรือยัง แล้วตอบเป็นตาราง

1. db/schema.sql
2. ฟอร์มลงทะเบียน (src/app/register/page.tsx)
3. ตารางในหน้าแอดมิน (src/app/admin/page.tsx)
4. ไฟล์ CSV ที่ส่งออก

ที่ไหนที่ยังขาด ให้บอกฉัน อย่าเพิ่งแก้
```

---

### P4-6 · สร้างเช็กลิสต์ทดสอบด้วยตาของตัวเอง

**ใช้ตอน:** อยากได้เช็กลิสต์ที่ตรงกับระบบของตัวเอง ไม่ใช่ของกลาง

```text
จากไฟล์ requirements.md สร้างเช็กลิสต์สำหรับทดสอบด้วยมือบนเบราว์เซอร์
เขียนเป็นตาราง 3 คอลัมน์: ทำอะไร · คาดว่าจะเกิด · กติกาข้อไหน

เงื่อนไข
- ทุกข้อต้องทำได้จริงในเบราว์เซอร์ ไม่ต้องเปิด terminal
- ต้องมีข้อที่ทดสอบฟิลด์ส่วนตัวของฉันด้วย
- เรียงจากข้อที่ทำเร็วที่สุดไปช้าที่สุด

เขียนเป็นไฟล์ test-checklist.md ที่รากโปรเจกต์
```
