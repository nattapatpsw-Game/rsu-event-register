# กติกาโปรเจกต์ — {{ชื่องานของคุณ}}

> **วิธีใช้ไฟล์นี้**
> 1. คัดลอกไฟล์นี้ไปวางที่ **รากของโปรเจกต์** แล้วเปลี่ยนชื่อเป็น `AGENTS.md`
> 2. แทนที่ทุกจุดที่เป็น `{{...}}` ด้วยของตัวเอง (มี 4 จุด)
> 3. ลบกล่องคำแนะนำนี้ทิ้ง
> 4. สั่ง agent ว่า **"อ่าน AGENTS.md กับ requirements.md ก่อนเริ่มงาน"** ทุกครั้งที่เปิดแชทใหม่
>
> `AGENTS.md` เป็นมาตรฐานกลาง — Antigravity, Claude Code, Codex และเครื่องมืออื่นอ่านไฟล์นี้เหมือนกันหมด
> ถ้าเครื่องมือของคุณใช้ `CLAUDE.md` ให้สร้างไฟล์ `CLAUDE.md` ที่มีบรรทัดเดียวว่า `@AGENTS.md`

## 0. อ่านอะไรก่อนเริ่มงานทุกครั้ง

1. `requirements.md` — สเปกและกติกา R1–R5
2. `design.md` — โครงหน้าจอและ flow
3. `db/schema.sql` — โครงตารางจริง ห้ามเดาชื่อคอลัมน์เอง
4. ไฟล์นี้

ถ้าคำสั่งของฉันขัดกับ 4 ไฟล์นี้ ให้หยุดแล้วถามก่อน อย่าเลือกข้างเอง

## 1. Stack ที่ล็อกไว้ — ห้ามเปลี่ยน

- Next.js **App Router** (ไม่ใช่ Pages Router) + TypeScript `strict`
- Tailwind CSS v4 — ตั้งค่าสีใน `src/app/globals.css` ใต้ `@theme inline` ไม่มี `tailwind.config.js`
- Supabase (PostgreSQL) เป็นฐานข้อมูล
- Deploy บน Vercel
- **ห้ามเพิ่ม library ใหม่โดยไม่ถามฉันก่อน** ทุกครั้ง ไม่มีข้อยกเว้น
- ถ้าคิดว่ามีทางที่ดีกว่า ให้เสนอมา แต่อย่าเปลี่ยนเอง

## 2. โครงไฟล์

```
src/app/            หน้าจอ   (ชื่อโฟลเดอร์ตัวพิมพ์เล็ก ห้ามเว้นวรรค ห้ามภาษาไทย)
src/app/api/        route handler ฝั่งเซิร์ฟเวอร์
src/lib/db.ts       ★ โค้ดที่คุยกับฐานข้อมูล อยู่ที่นี่ที่เดียว
src/lib/validate.ts ★ ตรรกะตรวจข้อมูล อยู่ที่นี่ที่เดียว
db/                 schema.sql · rls.sql · seed.sql
public/             รูปและโลโก้
```

- import ในโปรเจกต์ใช้ `@/` ห้ามใช้ `../../..`
- ห้ามสร้างไฟล์ใหม่ที่รากโปรเจกต์ถ้าฉันไม่ได้สั่ง
- ห้ามสร้าง README หรือไฟล์สรุปงานให้ตัวเองโดยไม่ได้สั่ง

## 3. กติกา R1–R5 — ต้องบังคับทั้งที่ server และที่ฐานข้อมูล

| | กติกา | ต้องกันที่ไหน |
|---|---|---|
| R1 | อีเมลซ้ำในกิจกรรมเดียวกัน ลงทะเบียนไม่ได้ | เทียบแบบ **case-insensitive** + unique index `(event_id, lower(email))` |
| R2 | ที่นั่งเต็มแล้วต้องปิดรับ | นับก่อน insert ที่ฝั่งเซิร์ฟเวอร์ + trigger ที่ฐานข้อมูล |
| R3 | ชื่อ/อีเมล/เบอร์ บังคับกรอก · อีเมลถูกรูปแบบ · เบอร์ 10 หลัก | ตรวจทั้งในฟอร์มและที่เซิร์ฟเวอร์ + `check` ที่ฐานข้อมูล |
| R4 | หน้าแอดมินต้องใส่รหัสผ่านก่อนเข้า | ตรวจที่เซิร์ฟเวอร์ทุก request + ไม่ให้ `anon` อ่านตารางผู้ลงทะเบียน |
| R5 | รหัสลงทะเบียนห้ามซ้ำ | สุ่มใหม่เมื่อชน + unique index |

- ห้ามเทียบอีเมลแบบ case-sensitive
- เต็มคือ `taken >= capacity` ห้ามใช้ `>`
- เบอร์โทรเก็บเป็น `text` เสมอ ห้ามเป็น `number` (เลข 0 ข้างหน้าจะหาย)
- ทุกครั้งที่แก้โค้ดที่แตะกติกาข้อไหน ให้บอกในคำตอบว่าแตะข้อไหน

## 4. ฐานข้อมูลและความปลอดภัย

- **ห้ามแก้ schema โดยไม่ถามฉันก่อน** — เสนอ SQL มาก่อน แล้วแก้ที่ `db/schema.sql` เป็นแหล่งความจริงเดียว
- ตารางผู้ลงทะเบียน **อ่าน/เขียนได้จากฝั่งเซิร์ฟเวอร์เท่านั้น** ถ้าเบราว์เซอร์ต้องใช้ ให้ทำ route handler ใต้ `src/app/api/`
- คีย์ที่ขึ้นต้นด้วย `NEXT_PUBLIC_` ผู้ใช้ทุกคนเห็นได้ — **ห้ามเอา service role key ใส่ตัวแปรที่ขึ้นต้นแบบนั้น และห้ามให้โผล่ในไฟล์ที่มี `"use client"`**
- **ห้ามปิด RLS หรือเปิด policy แบบ `using (true)` ให้ตารางผู้ลงทะเบียน เพื่อให้โค้ดรันผ่าน** ติดสิทธิ์เมื่อไหร่ให้บอกฉัน
- ห้าม log ชื่อ อีเมล เบอร์โทร ลง console
- ห้าม commit `.env.local` เพิ่มตัวแปรใหม่เมื่อไหร่ ให้เพิ่มชื่อ (ไม่ใส่ค่า) ลง `.env.example` ด้วย

## 5. ภาษาและธีมบนหน้าจอ

- **ข้อความที่ผู้ใช้เห็นทั้งหมดเป็นภาษาไทย** รวมข้อความ error และ placeholder
- ชื่อตัวแปร ฟังก์ชัน คอมเมนต์ และ commit message เป็นภาษาอังกฤษ
- ใช้ฟอนต์ที่มี glyph ไทย (`Noto Sans Thai`) ห้ามเปลี่ยนไปใช้ฟอนต์ที่ไม่มีภาษาไทย
- ห้าม hardcode สีเป็นเลข hex ในไฟล์ component — อ่านจากตัวแปรธีมใน `globals.css`
- วันที่แสดงด้วย locale `th-TH`

### ของฉันเอง — เปลี่ยน 4 จุดนี้

- ชื่องาน: `{{ชื่องานของคุณ}}`
- สีหลักของธีม: `{{#RRGGBB}}`
- โลโก้: `public/{{ชื่อไฟล์โลโก้}}`
- ฟิลด์เพิ่มของฉันในฟอร์มลงทะเบียน: `{{ชื่อฟิลด์ เช่น shirt_size}}`
  → ฟิลด์นี้ต้องมีครบทั้ง 4 ที่: `db/schema.sql` · ฟอร์มลงทะเบียน · ตารางหน้าแอดมิน · ไฟล์ CSV ที่ส่งออก

## 6. คุณภาพโค้ดที่ทำให้ deploy ไม่พัง

Vercel รัน `next build` ซึ่งรัน ESLint และ TypeScript ด้วย **error ตัวเดียว = deploy ไม่ขึ้น**

- ห้ามใช้ `any` — ใช้ชนิดจริงหรือ `unknown` แล้ว narrow
- ห้ามใช้ `<img>` — ใช้ `next/image`
- ห้ามเหลือ `console.log` และตัวแปรที่ไม่ได้ใช้
- ห้ามใช้ `alert()` / `confirm()` เป็น UI จริง
- **ห้ามปิด lint rule หรือใส่ `ignoreDuringBuilds` เพื่อให้ build ผ่าน** ให้แก้ที่ต้นเหตุ
- ก่อนบอกว่าเสร็จ ให้รัน `npx tsc --noEmit` และ `npm run lint` แล้วรายงานผลจริง

## 7. วิธีทำงานกับฉัน

- **ทำทีละฟีเจอร์** หนึ่งคำสั่ง = หนึ่งงาน
- ก่อนแก้ไฟล์ ให้บอกก่อนว่าจะแตะไฟล์ไหนบ้าง
- **ห้ามลบหรือเขียนทับโค้ดที่ไม่เกี่ยวกับงานที่สั่ง** เจอของที่คิดว่าผิดนอกขอบเขต ให้รายงาน อย่าแก้เอง
- **ห้ามใส่ข้อมูลตัวอย่างปลอมค้างไว้ในโค้ด** (mock array, ชื่อคนสมมติ, รหัสผ่านโชว์บนหน้าจอ)
- ห้ามแต่งชื่อฟังก์ชันหรือ API ขึ้นมาเอง ไม่แน่ใจให้เปิดเอกสารจริงหรือถามฉัน
- แก้บั๊กเดิมไม่สำเร็จ **3 ครั้ง** ให้หยุด อธิบายสาเหตุที่แท้จริงก่อน ห้ามเดาต่อ
- เมื่อฉันส่ง error มา ให้อธิบายสาเหตุก่อน อย่าเพิ่งแก้โค้ด
- **จบทุกฟีเจอร์ ให้เตือนฉันให้ commit** พร้อมเสนอข้อความ commit
- ห้ามรัน `git commit` / `git push` / `git reset` เองโดยไม่ได้สั่ง

## 8. Definition of Done

1. `npx tsc --noEmit` ผ่าน
2. `npm run lint` ไม่มี error
3. `npm run build` ผ่าน
4. ทดสอบด้วยมือในเบราว์เซอร์แล้วได้ผลจริง (บอกมาว่าทดสอบอะไร)
5. กติกา R1–R5 ข้อที่เกี่ยวข้องยังทำงานอยู่
6. เตือนให้ commit

ห้ามตอบว่า "เสร็จแล้ว" ถ้ายังไม่ได้รันคำสั่งจริงในข้อ 1–3
