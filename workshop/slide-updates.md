## B. สไลด์ที่ควรเพิ่มใหม่ (3 แผ่น)

1. **"รหัสผ่านที่เช็กในเบราว์เซอร์ ไม่ใช่รหัสผ่าน"** — วางระหว่างสไลด์ 33 กับ 34
   สาธิตสด: เปิด DevTools → Sources → ค้นคำว่า `admin1234` ในเวอร์ชันที่ AI เขียนให้ตอนแรก
   นี่คือสไลด์ที่ทำให้ R4 มีน้ำหนัก และปูทางไปสไลด์ 86 ตั้งแต่ช่วงเช้า

2. **"กติกาอยู่ชั้นไหน"** — ตารางเดียวกับใน `design.md` หัวข้อ 4
   client กันคนพิมพ์ผิด · server กันคนยิง API ตรง · DB กันคนกดพร้อมกัน
   ถ้ากติกาไหนมีแค่ชั้นบนสุด ถือว่ายังไม่มี

3. **"ที่นั่งเต็มพร้อมกัน 5 คน"** — ปูทาง B2 ให้ลึกขึ้น
   นับแล้วค่อย insert = 2 คำสั่งแยกกัน ถ้า 5 คนกดพร้อมกันตอนเหลือที่สุดท้าย จะผ่านทั้ง 5

## C. ของที่ต้องเตรียมเพิ่มจากภาคผนวก (สไลด์ 94)

สไลด์ 94 ระบุไว้แล้ว 7 อย่าง ต่อไปนี้คือของที่ยังขาดอีก:

- [ ] **บัญชี Supabase + GitHub + Vercel ให้นักศึกษาสมัครล่วงหน้า** — ใส่เป็นการบ้านก่อนวันงาน พร้อมภาพหน้าจอทีละขั้น (งบเวลา 6 ขั้นไม่มีช่องให้สมัครบัญชีหน้างานเลย)
- [ ] **ตัดสินใจเรื่อง test framework** — ขั้นที่ 4 ให้เวลา 45 นาที แต่ `package.json` ไม่มี test runner เลย
      เลือกอย่างใดอย่างหนึ่งแล้วเขียนลงสไลด์: (ก) manual checklist ตาม `workshop/test-cases.md` อย่างเดียว — ปลอดภัยกว่า
      (ข) ติดตั้ง vitest — ต้องเผื่อเวลาลง dependency อีก 10 นาที และขัดกับกฎ "ห้ามเพิ่ม library" ที่เพิ่งสอนไปตอนเช้า
- [ ] **แผนสำรองตอนติดตั้ง Antigravity CLI ไม่ผ่าน** (สไลด์ 40–45) — `winget` บนเครื่องที่ไม่มีสิทธิ์แอดมิน หรือเน็ตห้องอบรมช้า จะทำให้ตกขบวนตั้งแต่ยังไม่เริ่ม เตรียมทางที่สองไว้ (เว็บ agent หรือเครื่องสำรอง)
- [ ] **ซ้อม `npm run build` บนเครื่องที่ยังไม่มี `node_modules`** จับเวลาจริงไว้ จะได้รู้ว่าต้องเผื่อกี่นาที
- [ ] **ตรวจว่าห้องอบรมเข้า `fonts.googleapis.com`, `registry.npmjs.org`, `*.supabase.co`, `vercel.com` ได้** ถ้าบล็อกตัวใดตัวหนึ่งคือจบทั้งวัน
- [ ] **ใบ PDPA/ข้อความยินยอม** ที่จะใช้จริงในระบบของนักศึกษา — ระบบเก็บข้อมูลเพื่อนในห้องจริง ไม่ใช่ข้อมูลสมมติ
- [ ] **ข้อตกลงว่าจะลบข้อมูลเมื่อไหร่** หลังจบงาน ใครลบ ลบยังไง (สอนคู่กับสไลด์ 87)
