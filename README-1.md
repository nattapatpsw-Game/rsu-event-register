## ลำดับการใช้ในวันอบรม

| ขั้น | เปิดไฟล์ไหน | ได้อะไรกลับมา |
|---|---|---|
| **1 วิเคราะห์** | `prompts.html` → แท็บ **วิเคราะห์** | `requirements.md` ของตัวเอง |
| **2 ออกแบบ** | แท็บ **ออกแบบ** + `templates/AGENTS.template.md` | `design.md` · `db/schema.sql` · `AGENTS.md` |
| — | รัน `templates/schema.sql` → `rls.sql` → `seed.sql` ใน Supabase (ห้ามสลับลำดับ) | ตารางจริงในฐานข้อมูล |
| — | Supabase → Authentication → Users → Add user แล้วรันท่อนท้ายของ `seed.sql` | บัญชีผู้ดูแลสำหรับหน้าแอดมิน |
| **3 เขียนโปรแกรม** | แท็บ **เขียนโปรแกรม** ทีละงาน | ระบบที่กรอกฟอร์มแล้วชื่อขึ้นหน้าแอดมิน |
| **4 ทดสอบ** | แท็บ **ทดสอบ** + `worksheets/test-cases.md` | ตาราง test case ที่เติมช่อง "เกิดจริง" ครบ |
| **5 แก้บั๊ก** | แท็บ **แก้บั๊ก** | บั๊ก B1–B3 หาย และอธิบายได้ว่าเกิดจากอะไร |
| **6 Deploy** | แท็บ **Deploy** | URL จริงที่เปิดจากมือถือได้ |

## 3 ประโยคที่จำไว้ใช้ได้ทั้งวัน

ต่อท้าย prompt ไหนก็ได้ ไม่ต้องจำทั้งหมด จำ 2 ข้อแรกพอ

1. **`แตะได้แค่ไฟล์ [ชื่อไฟล์] ห้ามแตะไฟล์อื่น`**
   กันบั๊กที่เจ็บที่สุด คือ agent ไปลบโค้ดที่หน้าอื่นเรียกใช้อยู่
2. **`อย่าเพิ่งเขียนโค้ด อธิบายให้ฉันฟังก่อน`**
   ถ้ามันอธิบายไม่ได้ แปลว่ากำลังเดา — เดาต่ออีกกี่รอบก็ไม่เจอ
3. **`ถ้าสเปกข้อไหนกำกวมจนทำต่อไม่ได้ ให้ถามฉัน อย่าเดาเอง`**
   AI ถูกฝึกมาให้ตอบเสมอ ต้องบอกตรง ๆ ว่าอนุญาตให้ถามได้

## โปรเจกต์นี้ไม่มีคีย์ลับ

ทั้งระบบใช้ตัวแปร environment แค่ 2 ตัว และทั้งคู่เป็นค่าที่ใครเปิดเว็บก็เห็นได้

```
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
```

ความปลอดภัยจึงไม่ได้มาจากการซ่อนคีย์ แต่มาจาก 3 ชั้นนี้แทน

| ชั้น | อยู่ที่ไหน | กันอะไร |
|---|---|---|
| Row Level Security | `templates/rls.sql` | ใครอ่าน/แก้แถวไหนได้ |
| ฟังก์ชัน `security definer` | `templates/schema.sql` | ประตูเดียวที่เขียนตารางผู้ลงทะเบียนได้ |
| Supabase Auth + ตาราง `admins` | Dashboard + ท้ายไฟล์ `seed.sql` | รหัสผ่านแอดมินอยู่นอกโค้ดทั้งหมด |

> ถ้าวันไหน agent เสนอให้เพิ่ม `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_SECRET_KEY`
> หรือ `ADMIN_PASSWORD` — นั่นคือสัญญาณว่ามันกำลังแก้ปัญหาผิดชั้น ให้หยุดแล้วทบทวนก่อน
